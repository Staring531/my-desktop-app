# UI/UX 设计评审与就绪门槛

## Reviewer 角色
独立只读，只返回 findings。不得编辑正式文件、访谈用户、作产品决策或写代码。平台支持时使用工具级只读限制；提示词约束不构成沙箱。

## 评审门槛
结构设计、获批 Visual Direction、获批 Token/核心组件基线、线框/页面规格、高保真视觉与交互/状态规格、无障碍/窗口行为、验证证据和需求追溯形成一致版本后调用。

## 评审清单
1. PRD 范围和角色/权限一致性。
2. 所有适用 PRD 流程均有体现；每个相关 AC 映射到页面/组件/交互或合理的非 UI 行为说明。
3. 遵循已批准 Visual Direction，且未复制受保护品牌或引入未支持的产品模式。
4. Token 分类合理；Semantic/Component 别名使用正确；识别缺失 Token 和未记录原始值。
5. 组件复用一致；变体、状态、无障碍、键盘和缩放行为有定义。
6. 字体、间距、对齐、层级、信息密度、表面和图标跨页面一致。
7. 适用的成功/失败/取消/空/加载/禁用/拒绝状态。
8. 本地时间、歧义/不存在时间、未修改时间瞬间。
9. 破坏性操作的确认和结果反馈真实。
10. 键盘、焦点、标签、对比度和非颜色线索。
11. 符合已批准架构和模块边界。
12. 与实施任务对齐；计划变更只提出建议，不得静默应用。
13. 区分设计产物验证和真实运行时截图对比。

## Finding 格式
ID、严重程度（CRITICAL/HIGH/MEDIUM/LOW）、页面/产物、PRD AC 和设计引用、具体场景、证据、用户影响、建议、是否需要产品决策。

## 就绪结果
报告 PRD/技术追溯、Token/组件/页面符合性、页面/流程/交互/状态/无障碍覆盖、验证证据、评审处置、Implementation Plan 对齐、剩余风险和待确认问题。用户明确批准前保持 READY FOR USER REVIEW。UI/UX 获批不授权编码。
