# UI/UX 设计评审与就绪门槛

## Reviewer 角色
独立只读，只返回 findings。不得编辑正式文件、访谈用户、作产品决策或写代码。平台支持时使用工具级只读限制；提示词约束不构成沙箱。

## 评审门槛
信息架构/流程、页面清单/线框、视觉/设计系统、交互/状态、无障碍/窗口行为、追溯关系、风险和待确认问题形成一致版本后调用。

## 评审清单
1. PRD 范围一致性。
2. 角色和权限一致性。
3. 所有适用 PRD 流程均有路径。
4. 每个相关 AC 都映射到页面或交互。
5. 适用的成功/失败/取消/空/加载/禁用/拒绝状态。
6. 本地时间、歧义/不存在时间、未修改时间瞬间。
7. 破坏性操作的确认和结果反馈真实。
8. 键盘、焦点、标签、对比度和非颜色线索。
9. 符合已批准架构和模块边界。
10. 与实施任务对齐；计划变更只提出建议，不得静默应用。

## Finding 格式
ID、严重程度（CRITICAL/HIGH/MEDIUM/LOW）、页面/流程、PRD AC 和设计引用、具体场景、用户影响、建议、是否需要产品决策。

## 就绪结果
报告 PRD/技术追溯、页面/流程/交互/状态/无障碍覆盖、评审处置、Implementation Plan 对齐、剩余风险和待确认问题。用户明确批准前保持 READY FOR USER REVIEW。UI/UX 获批不授权编码。
