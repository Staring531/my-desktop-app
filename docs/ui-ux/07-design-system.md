# Design System

## Scope
A lightweight application-level system, not a generalized component platform.

## Tokens
Document semantic colors (background/surface/text/muted/border/focus/success/warning/error/busy/free), typography, spacing/sizing, radii/borders/elevation, motion, and reduced-motion behavior.

## Component patterns
Only components required by approved screens: app shell/navigation; buttons; text/email/date/time inputs; selectors and visibility controls; event rows/cards and busy/free indicators; member/invitation items; dialogs; validation/notifications; loading/empty/error/no-access states.

## Component specification
Record purpose, anatomy, variants, states, keyboard behavior, accessible name/description, resizing behavior, and usage examples.

## Accessibility baseline
Keyboard operation and logical focus order; visible focus; programmatic labels and associated errors; sufficient contrast; never convey busy/free, visibility, or permission by color alone; respect reduced motion.
