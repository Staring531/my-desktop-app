# 设计 Token

- 阶段：3 — Design Tokens 与核心组件系统，用户批准门禁 2
- 日期：2026-11-20
- 状态：用户于 2026-11-20 批准。该批准不授权应用代码、线框接受或高保真页面。
- 机器可读来源：`tokens/design-tokens.json`
- 技术栈：桌面渲染层是 Electron 上的 React，仓库中没有 CSS 框架、图标字体或 Token 编译器。日后的映射提案是普通 CSS 自定义属性。本阶段不安装依赖，也不写应用代码。
- 英文 `10-design-tokens.md` 是规范文本。本文件是对照译文。

## 1. 如何阅读这三层

Primitive Token 保存原始值。Semantic Token 命名用途并指向 Primitive。Component Token 指向 Semantic Token；共享尺寸已经是 Primitive 尺寸时除外。将来的页面规格使用 Semantic 或 Component Token。

只有一套浅色主题。没有深色值，也没有主题偏好 Token。

## 2. 颜色

底色是 `#F4F5F6`。主要文字是 `#1B1F24`。唯一强调色是 `#0F5F66`，用于主要按钮、键盘焦点环和选中行的标记。它不用于忙碌、空闲、可见性或失败。

| 配对 | 色值 | 设计时对比度 |
|---|---|---|
| 主要文字对底色 | `#1B1F24` 对 `#F4F5F6` | 约 14.6:1 |
| 次要文字对底色 | `#3E4651` 对 `#F4F5F6` | 约 8.7:1 |
| 辅助文字对底色 | `#4A5160` 对 `#F4F5F6` | 约 7.2:1 |
| 强调色上的白字 | `#FFFFFF` 对 `#0F5F66` | 约 7.3:1 |
| 危险文字对底色 | `#8E1B1B` 对 `#F4F5F6` | 约 8.1:1 |

这些比值使用 sRGB 相对亮度公式。它们属于提案，不是认证审计。发丝线 `#D0D5DB` 分隔区域，不是文字颜色。忙碌和空闲使用同一种主要文字颜色；差别在于文字和组件 C-06 的记号。

## 3. 字体、间距和形状

一种操作系统无衬线字体。三种角色：标题 16/20、字重 600；正文 13/18、字重 400；辅助 12/18、字重 400。没有网络字体，也没有展示型大标题。

间距阶梯是 4、8、12、16、24 和 32 px。控件和行高 32 px。控件圆角 4 px，窗口圆角 0。没有阴影。反馈时长是 0 ms，减少动效时同样如此。

`size.window-width` 和 `size.window-height` 记录现有的 1200×800 Electron 窗口。它们不要求新的窗口尺寸。

## 4. 使用规则

- PRD 加以区分的状态同时用文字写出。
- 强调色标记主要操作和选中行。选中行还有一条 2 px 的前导条，因此浅色底不是唯一线索。
- 失败和破坏性操作使用危险文字和该操作的名称。它们不引入第二种填充品牌色。
- 未经新的提案，不增加阴影、第二种强调色，或 `motion.feedback` 以外的动效时长。
- JSON 中的别名是唯一的间接引用。存在 Semantic 颜色时，页面不直接指向 Primitive 颜色。

## 5. 本提案不决定的事

Q-04，即移除、删除或解散前的确认步骤，仍然开放。没有为它预留确认表面的 Token。线框和高保真页面属于 Stage 4 和 Stage 5。
