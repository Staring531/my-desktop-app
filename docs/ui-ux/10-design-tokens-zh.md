# Design Tokens（设计令牌）

## 状态与权威
用户在 Design System Gate 批准前，Token 基线保持 DRAFT。机器可读取文件为 `tokens/design-tokens.json`。不得将示例值写入应用或把临时值当作已批准值。

## 必需层级
1. **Primitive Tokens（原始令牌）：** 按需定义颜色、字体、间距、尺寸、圆角、边框、层级、动效、图标和层叠顺序的原始值。
2. **Semantic Tokens（语义令牌）：** 为画布/背景、表面、文字、边框、焦点、操作、状态、忙闲和禁用状态定义用途别名。
3. **Component Tokens（组件令牌）：** 引用语义令牌的组件专属别名，例如按钮高度/背景/圆角或输入框边框/焦点。

## 规则
- Stage 0 确认实际技术栈后，才能选择 Token 格式和运行时映射方式。
- 尽可能使用现有样式/主题机制；设计阶段不得安装依赖。
- 页面和组件规格应引用 Semantic/Component Token，而不是原始 Primitive 值。
- 每个 Token 都要有稳定名称、值、类型/单位、说明、用途和状态（PROPOSED/APPROVED/DEPRECATED）。
- 颜色 Token 必须检查对比度，且不得作为业务状态的唯一表达方式。
- 定义尺度，避免互不相关的一次性数值和 Token 过度膨胀。
- 记录别名、继承、主题适用范围（仅限已批准主题）及迁移/弃用规则。
- 每个原始值例外都必须记录位置、理由、影响和批准/处置情况。
- JSON 必须有效且确定；JSON 文件内不得放注释或说明文字。

## 评审清单
Schema 有效性；重复/未使用 Token；未解析引用；无效单位；语义别名是否映射原始值；组件别名是否映射语义值；对比度和状态覆盖；不存在未批准的最终值。
