- 状态：用户于 2026-11-20 连同 UI/UX 设计包一并接受。这些契约不增加业务规则。该接受不授权应用代码。
- 视觉：`05-visual-design.md`。页面：`12-page-specifications.md`。
- 失败的命令在发出它的会话上，用 C-08 显示结果代码。代码的用词就是代码本身，这是已批准错误契约的要求。其他会话看不到未发送的字段。
- 用户于 2026-11-20 关闭 Q-04。移除、删除和解散在同一表面确认后才发送。确认不是新目的地，也不是授权边界。放弃含糊时间选择仍回到 S-05，并丢掉未发送的编辑。英文 I-15 是这条规则的规范。
- 英文 `06-interaction-specifications.md` 是规范文本。本文件是对照译文。评审之后英文文件又有修订。若两者冲突，以英文为准。

## 1. 共用命令行为

渲染器发送一条命令，然后等待。该命令进行中时，发出它的按钮显示进行中动词，并忽略再次点击、Enter 和 Space。取消和 Escape 只在命令发出之前可用。发出之后，表面等待结果，这样本地取消不能声称一条已排队的写入没有发生。

拒绝不改变已存储的记录，并保留未发送的编辑。成功时按新投影重绘。C-08 用来显示代码，不用作第二条成功消息。

| 控件 | 进行中动词 |
|---|---|
| 绑定 | 正在绑定 |
| 创建团队 | 正在创建 |
| 接受 | 正在接受 |
| 拒绝 | 正在拒绝 |
| 邀请 | 正在邀请 |
| 取消邀请 | 正在取消 |
| 设为维护者 | 正在设为维护者 |
| 移除 | 正在移除 |
| 解散 | 正在解散 |
| 保存 | 正在保存 |
| 删除 | 正在删除 |

Tab 按视觉顺序移动。焦点在按钮上时，Enter 和 Space 激活它。单行字段中的 Enter 在 S-01，以及 S-06 的标题和地点字段上，激活主要按钮。S-05 邀请字段中的 Enter 激活邀请，不激活新建事件。描述字段中的 Enter 插入换行，不激活保存。焦点从“打开另一个会话”开始，然后按表面从上到下；S-01 除外，电子邮件字段在先，“打开另一个会话”跟在表面之后。这个例外让新窗口的绑定任务落在第一个字段上。

C-08 在显示代码时是一个 alert。被拒绝字段的无障碍描述指向这段文字。边框变色不是唯一线索。

推送的投影刷新 S-05，并按已经在查看的时刻重新计算 `busyAt`。本会话仍有访问权时，打开的 S-06 保留未发送的编辑。投影取消本会话的访问权，或解散记录时，替换 S-06。事件字段不再留下。替换之后到达的拒绝，用 C-08 显示在替换后的表面上，不带事件字段。

`replace-failed` 与其他代码一样显示。先前的文件保留，未发送的编辑保留，操作者可以再次提交该命令。设计不会静默重试。

## 2. 交互

### I-01 绑定这个会话

- 目的：为这个窗口存储一个电子邮件，或者保持未绑定。
- 操作者：未绑定窗口的操作者。流程 F-01。表面 S-01。
- 输入：已输入的电子邮件。命令是只带该请求电子邮件的 `bind`。
- 发送前：空字段不发送。C-08 显示 `unusable-email`，字段边框改为危险色，字段保持空白。
- 结果：`unusable-email` 或 `bind-rejected` 留在 S-01 并保留已输入的值。成功时把规范电子邮件存入会话，并按投影替换表面：S-02、S-03、S-04 或 S-05。
- 取消：清空字段不写入。这个交互不写团队记录。
- 不得发送：操作者电子邮件、时区、世代或团队命令。
- 追溯：TD-002。通过选择电子邮件支持 AC-004、AC-015 和 AC-019。绑定不写团队记录。

### I-02 打开另一个会话

- 目的：打开一个新的未绑定窗口。
- 操作者：任意当前窗口。每个表面上的外壳控件。
- 输入：无。新窗口不接收电子邮件，也不接收未发送字段。
- 结果：新窗口是 S-01。当前窗口保持原样。
- 追溯：TD-001。这不是第二个团队，也不是另一台电脑。

### I-03 创建团队

- 目的：用已绑定的电子邮件创建这一个团队。
- 操作者：记录不存在或已解散时的已绑定会话。流程 F-02。表面 S-02。
- 输入：无。`createTeam` 不发送电子邮件、时区或世代。
- 结果：成功后为该创建者显示 S-05。`unusable-email`、`team-already-active` 或 `generation-mismatch` 以该代码留在当前表面。拒绝时记录不变。
- 追溯：BR-1，AC-001，AC-002，AC-003，AC-050。AC-002 是记录已经活动时的尝试。那个窗口不在一张能够成功的创建表单上。

### I-04 接受或拒绝这份邀请

- 目的：接受并进入名册，或者拒绝。
- 操作者：受邀电子邮件，且不是当前成员。流程 F-03。表面 S-03。
- 输入：`acceptInvite` 或 `declineInvite`。没有名册或事件命令。
- 结果：接受成功显示 S-05，包括已经结束的、以及加入前创建的团队可见事件。拒绝成功且不再有访问权时显示 S-04。`no-matching-invite` 或 `not-allowed` 留在 S-03。
- 追溯：BR-2，AC-004，AC-005，AC-030，AC-032，AC-034，AC-036。

### I-05 没有团队访问权

- 目的：说明这个已绑定的电子邮件不能查看活动中的团队。
- 操作者：不是成员，也没有待处理邀请。流程 F-01 和 F-07。表面 S-04。
- 输入：无。不渲染写入控件，包括创建。
- 结果：日后若投影出现给同一电子邮件的待处理邀请，表面换成 S-03。会话电子邮件不变。
- 追溯：BR-5，AC-015，AC-019。

### I-06 查看忙闲

- 目的：在一个时刻显示每个当前成员是忙碌还是空闲。
- 操作者：当前成员。流程 F-06。表面 S-05。
- 输入：首次绘制时无。忙闲板从当前时间开始。“现在”“看开始”和“看结束”只改变正在查看的时刻。它们不写入，也不打开 S-06。
- 计算：忙闲板对该时刻调用 `busyAt`。查看者自己的行计入该查看者的仅自己事件。其他每一行只使用团队可见事件。事件的结束时刻对该事件而言是空闲。已结束的事件留在事件列表中，不使当前时刻变为忙碌。
- 结果：已移除的所有者没有成员行。该所有者保留的团队可见事件留在事件列表中，并标出已存储的所有者电子邮件。
- 追溯：BR-6，AC-016，AC-017，AC-018，AC-040，AC-042，AC-045。时钟标签使用这一个投影时区。AC-042 不增加时区选择器。在这一台电脑上，两个会话共用该时区。

### I-07 维护者名册操作

- 目的：邀请、取消邀请、指定维护者、移除成员，或在唯一成员时解散。
- 操作者：投影表明该会话是维护者；解散除外，它只在唯一成员时渲染。流程 F-03、F-04、F-07。表面 S-05。
- 输入：邀请发送已输入的电子邮件。取消发送该待处理地址。指定和移除发送另一名成员。解散不另送电子邮件。普通成员看不到这些控件。
- 发送前：空的邀请字段不发送。C-08 显示 `unusable-email`。
- 留在 S-05 的结果代码：`unusable-email`、`already-member`、`invite-exists`、`no-matching-invite`、`not-allowed`。邀请成功后显示新的待处理行。指定成功后重绘权限。移除成功后去掉该成员行和该成员的仅自己事件。解散成功后表面换成 S-02，因为记录已解散。普通成员没有邀请、取消、移除或指定控件（AC-038）。维护者自己的行没有指定控件（AC-039）。
- 查看者自己的行没有“设为维护者”和“移除”。投影不再是唯一成员时，解散不出现。领域拒绝解散时显示 `not-allowed`，并且不写入。
- 追溯：BR-2，BR-3，BR-5，AC-006 到 AC-011，AC-019，AC-023，AC-033，AC-038，AC-039。对这些操作者，AC-010 和 AC-011 没有能够成功的控件。若一个过期控件仍被激活，结果就是拒绝。

### I-08 打开一个事件

- 目的：创建事件，或按投影中的一个事件 id 编辑。
- 操作者：当前成员，或对保留的团队可见事件进行保管的维护者。流程 F-05。表面 S-06 替换 S-05 的主体。外壳保持不变。
- 输入：“新建事件”打开创建表单。“编辑”打开该行的事件 id。渲染器不生成 id。
- 命令发出之前，取消和 Escape 回到 S-05，并且只显示已存储的事件。
- 追溯：BR-4，BR-5。

### I-09 选择可见性

- 目的：创建时必须明确选择可见性。
- 操作者：正在创建事件的成员。表面 S-06。
- 输入：C-05，“团队”或“仅自己”。没有预选项。方向键在组内移动。该组自己不提交。
- 发送前：未选择就按保存，不发送 `createEvent`。C-08 显示校验句“请选择团队或仅自己。”这句话不是领域代码。不会调用领域。
- 创建者编辑显示已存储的选择。不改动则保留该可见性。保管编辑不渲染该选择，也不能发送另一种可见性。
- 追溯：BR-4，AC-012，AC-020，AC-048。

### I-10 保存一个事件

- 目的：创建或修改一个事件。
- 操作者：身为当前成员的所有者，或保管中的维护者。表面 S-06。
- 输入：标题、地点、描述，以及只在该时钟被编辑过、或它正在补报刚刚要求的发生时刻时才发送的时钟。标题、地点和描述去掉外层空白。描述内部的换行保留。地点或描述可以为空后保存。结束时刻已经过去的时钟可以保存。命令不发送时区，也不发送渲染器生成的 id。保管不发送可见性变更；不会提供“把标题和另一种可见性一起发送”。
- 时钟输入：一行，`YYYY-MM-DD HH:mm`，使用投影时区。匹配的一行变成 `{ year, month, day, hour, minute }`。不匹配的文字不发送，C-08 显示 `invalid-local-time` 和该字段名。匹配的一行仍可能返回 `invalid-local-time`、`nonexistent-local-time` 或 `ambiguous-local-time`。事件行上的标签仍是投影给出的格式化时刻。它们不复用这个输入格式。
- 发送前：去掉外层空白后标题为空时，不另加第二条本地规则。保存会发出，并返回 `empty-title`；若 I-09 的可见性检查已经拦住创建，则不发出。结束不晚于开始时，命令返回 `end-not-after-start`。
- 结果：成功后回到 S-05，显示已存储的事件。`empty-title`、`end-not-after-start`、`nonexistent-local-time`、`invalid-local-time`、`not-allowed`、`event-not-found`、`generation-mismatch` 和 `dissolved` 以该代码留在 S-06。`ambiguous-local-time` 留在 S-06，并为返回的字段打开 I-11。未发送的编辑保留。
- 表单不提供重复事件或全天事件。不为那些代码提供控件。
- 追溯：BR-4，BR-5，AC-012，AC-013，AC-014，AC-020，AC-021，AC-029，AC-037，AC-043，AC-044，AC-048，AC-051。AC-028 在 I-11 继续。

### I-11 含糊的本地时间

- 目的：为命令刚刚报告的那一个字段收集 `earlier` 或 `later`。
- 操作者：同一个 S-06 编辑者。这是 S-06 的一个状态，不是新表面。
- 输入：该字段下的 C-05。没有预选项。若两个时钟都含糊，命令先报告开始。结束时间的选择只在下一次提交仍然需要它时出现。
- 选择出现时页面不写入。下一次保存为被报告的字段发送发生时刻。在那次提交之前放弃选择、取消或按 Escape，都回到 S-05 并且不写入。
- 追溯：AC-028，AC-046。AC-046 也覆盖取消和失败的保存；查看者仍看到已存储的事件。

### I-12 删除一个事件

- 目的：删除当前打开的事件。
- 操作者：身为当前成员的所有者，或保管中的维护者。表面 S-06。
- 输入：针对打开的 id 的 `deleteEvent`。创建时没有该控件；操作者不能删除时也没有。
- 结果：成功后回到 S-05，且没有该事件。`not-allowed` 或 `event-not-found` 留在 S-06。没有确认步骤，因为 Q-04 开放。
- 追溯：BR-4，BR-5，AC-037，AC-047，AC-049。编辑和删除只渲染在该操作者可以更改的事件上。命令仍返回 `not-allowed` 时不写入。

### I-13 记录不可读

- 目的：停止团队界面，并且不创建替代团队。
- 操作者：拥有进程的操作者。流程 F-09。表面 S-07。
- 输入：无。没有修复，也没有创建控件。
- 结果：C-08 显示 `record-unreadable`。表面保持不动。
- 追溯：BR-7。

### I-14 已有写入者

- 目的：告诉操作者，这个进程已经拥有该记录。
- 操作者：收到 `second-instance` 之后的现有窗口。流程 F-09。表面 S-08。
- 输入：无。关闭或 Escape 去掉 C-09，并且不写入。
- 没有拿到锁的进程退出，并且没有页面。
- 追溯：BR-7。

## 3. 权限与失去访问权

控件只在当前投影允许该操作者尝试时渲染。命令完成后，失去成员身份的会话收到 S-04；若投影中有给同一电子邮件的待处理邀请，则收到 S-03。现在成为已解散记录的创建者的会话收到 S-02。不为了解释 `not-allowed` 而画出隐藏数据。
