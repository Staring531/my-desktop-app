# 页面规格

- 阶段：4 — 线框与页面规格
- 日期：2026-11-20
- 状态：用户于 2026-11-20 连同 UI/UX 设计包一并接受。这些页面组合已批准的组件。高保真处理见 `05-visual-design.md`。交互见 `06-interaction-specifications.md`。该接受不授权应用代码。
- 草图：`04-wireframes.md`。
- Token：只用 Semantic 和 Component Token。没有新的原始值。
- 用户于 2026-11-20 关闭 Q-04。移除、删除和解散在原处确认。没有页面增加确认目的地。
- 英文 `12-page-specifications.md` 是规范文本。本文件是对照译文。

共同行为：一个窗口是一个会话。C-08 出现在发出命令的表面上，不单独成页。另一条打开的会话只在命令完成之后收到新的投影。被拒绝的命令不改变已存储的记录。时区文字是投影中的那一个时区。操作者不能编辑它。

## S-01 绑定这个会话

- 操作者与入口：未绑定的窗口，包括由 `打开另一个会话` 打开的窗口。流程 F-01。
- 目标：为这个会话存储一个电子邮件，或者保持未绑定。
- 组件：C-01、C-03 电子邮件、C-02 主要按钮“绑定”、C-08。
- 布局：标题、字段、主要按钮、结果。密度遵循紧凑行高。
- 校验：空的、不可用的或不允许的电子邮件不会绑定。字段保留已输入的值。C-08 说明拒绝原因。
- 退出：成功后按投影进入 S-02、S-03、S-04 或 S-05。
- 键盘：电子邮件，然后是绑定。在字段中按 Enter 会激活绑定。
- 追溯：TD-002。绑定不写入团队记录。

## S-02 创建团队

- 操作者：记录不存在或已解散时的已绑定电子邮件。流程 F-02。
- 组件：C-01、正文中的只读会话电子邮件、C-02 主要按钮“创建团队”、C-08。
- 页面没有电子邮件字段。创建使用已绑定的电子邮件。
- 退出：成功后为该创建者显示 S-05。拒绝则留在 S-02。
- 追溯：BR-1、AC-001、AC-002、AC-003、AC-050。AC-002 不是这个页面；那种尝试发生在记录已经活动的时候。

## S-03 这份邀请

- 操作者：有待处理邀请、且不是当前成员的电子邮件。流程 F-03。
- 组件：C-01、受邀电子邮件的正文、C-02 主要按钮“接受”、C-02 安静按钮“拒绝”、C-08。
- 页面不显示名册、事件、忙闲或其他邀请。
- 退出：接受后显示 S-05，包括已经结束的、以及加入前创建的团队可见事件。拒绝后若不再有访问权则显示 S-04。失败则留在 S-03。
- 追溯：BR-2、AC-004、AC-005、AC-030、AC-032、AC-034、AC-036。

## S-04 没有团队访问权

- 操作者：团队活动期间，已绑定但既不是成员也没有待处理邀请的电子邮件。流程 F-01 和 F-07。
- 组件：C-01 和 C-08。没有主要按钮。
- 页面不提供创建、邀请、事件或忙闲。
- 退出：日后若同一电子邮件的投影包含待处理邀请，页面换成 S-03。会话电子邮件不变。
- 追溯：BR-5、AC-015、AC-019。

## S-05 团队工作区

- 操作者：当前成员。只有投影标明该操作者是维护者时，才渲染维护者控件。流程 F-03、F-04、F-06、F-07、F-08。
- 目标：查看一个时刻的忙闲，查看允许看到的事件，并且只发送该操作者被允许尝试的名册操作。
- 区域，从上到下：时刻读数和安静的“现在”；成员行；事件行；主要按钮“新建事件”；维护者的待处理邀请；维护者的邀请字段；唯一成员的“解散”。
- 组件：C-01、C-06、C-07、C-02、用于邀请电子邮件的 C-03、C-08。
- 时刻：忙闲板从当前时间开始。事件行上的 `看开始` 和 `看结束` 把忙闲板设为该事件的开始或结束。`现在` 把它回到当前时间。这些控件不写入，也不打开 S-06。
- 成员行：记号和“忙碌”或“空闲”，然后是成员姓名。查看者自己的行包含其仅自己可见的事件。其他每一行只用团队可见事件。已移除的所有者没有行。
- 事件行：可见性记号和词、标题、投影时区中的时钟标签，以及安静的“看开始”“看结束”和“编辑”。列表包括已结束的事件、该成员加入前创建的团队可见事件，以及该成员自己的仅自己可见事件。每个可编辑的行通过“编辑”携带事件 id。保留的团队可见事件在辅助文字中保留存储的所有者电子邮件。
- 维护者的行操作：对另一名当前成员使用安静的“设为维护者”；对另一名当前成员使用危险的“移除”。维护者自己的行没有这两项操作。每个待处理地址有一个安静的“取消邀请”。邀请是电子邮件字段旁边的安静按钮，不是第二个主要按钮。
- “解散”是危险按钮，只为唯一成员渲染。有两名或更多成员时它不出现。若提交时投影里已经不是唯一成员，则不写入，并由 C-08 说明。
- 没有事件时：忙闲板和“新建事件”仍然在。
- 被拒绝的名册命令留在 S-05，C-08 说明拒绝原因。
- 键盘：现在，每个成员行的操作，每个事件行的操作，新建事件，然后是维护者字段。这些区域在表面内部滚动。
- 追溯：BR-2、BR-3、BR-4、BR-5、BR-6；AC-006 到 AC-011、AC-016 到 AC-019、AC-023、AC-033、AC-038 到 AC-042、AC-045、AC-047。AC-042 的标签使用这一个投影时区。

## S-06 一个事件

- 操作者：当前成员创建新事件或编辑自己可以编辑的事件。维护者只能修改所有者已经不在的保留团队可见事件的文字、时钟和删除。流程 F-05。
- 入口：S-05 上的“新建事件”或“编辑”。外壳保留；这个页面替换 S-05 的主体。
- 组件：C-01、用于可见性的 C-05、C-03、C-04、C-02 主要按钮“保存”、C-02 安静按钮“取消”、可删除已有事件时的 C-02 危险按钮“删除”、C-08。
- 创建字段：可见性没有预选项、标题、地点、描述、开始、结束，以及只读的时区名称。保存需要一个可见性选择、去掉首尾空白后仍有字符的标题，以及晚于开始的结束时刻。空的地点和描述仍然可以保存。
- 创建者编辑：同样的字段，已存储的可见性处于选中状态。开始和结束先显示为文字。安静的“更改开始”或“更改结束”把其中一个值变成 C-04。未被更改的时钟在保存时省略，正在补报发生时刻的时钟除外。
- 保管编辑：可见性是只读的词“团队”。没有 C-05。维护者可以更改标题、地点、描述和已输入的时钟，或者删除。页面不提供改变可见性的命令。
- 含糊时间是这个页面的一种状态。C-05 在正在处理的字段下方提供“较早”和“较晚”，没有预选项。两个字段都含糊时，先处理开始时间。在后来的提交包含所需选择之前，页面不写入。不存在和无效的时间留在这个页面上，由 C-08 说明，并且不写入。
- 取消和 Escape 回到 S-05，并且只显示已存储的事件。
- 追溯：BR-4、BR-5；AC-012 到 AC-015、AC-020、AC-021、AC-028、AC-029、AC-037、AC-043、AC-044、AC-046、AC-048、AC-049、AC-051。

## S-07 记录不可读

- 操作者：拥有该进程的操作者。流程 F-09。
- 组件：C-01 和 C-08。没有创建控件，也没有团队区域。
- 页面留在原地。Version 1 没有修复操作。
- 追溯：BR-7。

## S-08 写入者已经存在

- 操作者：该进程处理 `second-instance` 之后，正在看已有窗口的操作者。流程 F-09。
- 组件：C-09 盖在会话已经打开的页面上，加上安静的“关闭”。
- 关闭会去掉通知，并且不写入。失败的进程没有页面。
- 追溯：BR-7。

## 偏差

没有。S-05 把维护者操作放在忙闲板和事件列表之后，使已批准的“忙闲板优先”工作区保持为同一个页面。这个顺序不增加目的地。
