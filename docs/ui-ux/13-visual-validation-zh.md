# 视觉验证

## 范围
本阶段验证设计产物和规格，不声称已实现应用通过像素级运行时验证。实际运行时截图对比必须等到另行授权 Coding & Testing 后执行。

## 设计阶段验证
1. **Token 完整性：** Token 文件有效、引用可解析、状态获批、语义/组件分层正确、没有未记录原始值。
2. **组件完整性：** 引用已批准组件、变体/状态一致、无障碍和键盘契约完整。
3. **页面一致性：** 字体、间距、对齐、层级、信息密度、表面、图标和反馈模式。
4. **覆盖度：** 每个范围内页面和适用状态均有体现。
5. **需求追溯：** PRD AC → 流程 → 页面 → 组件/交互 → 计划实施任务。
6. **桌面行为：** 支持的窗口约束、缩放、溢出、焦点和键盘行为。
7. **无障碍：** 对比度、标签、焦点可见性、非颜色线索，以及适用的减少动态效果要求。

## 证据
每项记录产物路径/版本、检查项、预期结果、实际观察、状态（PASS/FAIL/NOT CHECKED）、证据/引用和问题负责人。没有证据不得标记 PASS。

## 运行时验证交接
获得单独实施授权后，再定义确定性的窗口尺寸、测试数据、应用状态、截图方法、对比容差和回归责任。将实际截图与已批准高保真参考对比，报告偏差并在修复后复测。设计阶段不得增加截图工具或依赖。
