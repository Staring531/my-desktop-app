# 设计系统

## 目的与状态
面向已批准 Version 1 桌面 UI 的轻量应用级设计契约，不建设通用组件平台。用户于 2026-11-20 批准方向 L 以及 Token 与组件基线。用户于 2026-11-20 接受高保真和交互规格。它们在 `05-visual-design.md` 与 `06-interaction-specifications.md`。该接受不授权应用代码。

## 治理规则
- 先批准 Visual Direction，再确定最终 Token 值。
- Primitive、Semantic、Component 三层 Token 定义在 `10-design-tokens.md`，机器可读取文件为 `tokens/design-tokens.json`。
- 核心组件契约定义在 `11-component-specifications.md`。
- 页面必须使用已批准 Semantic/Component Token 和组件；偏差必须说明理由并记录处理结论。
- 英文文档为规范版本；对应中文翻译必须保持一致。
- 影响多个页面的变更必须进行影响分析并更新相关规格。

## Token 层级
1. **Primitive：** 原始颜色、间距、字体、圆角、边框、层级、动效和尺寸值。
2. **Semantic：** 用途别名，例如画布/表面/文字/边框/焦点/状态/操作。
3. **Component：** 引用语义 Token 的组件专属别名。

页面规格应引用 Semantic 或 Component Token，不直接引用原始 Primitive 值。批准前不得编造最终值。

## 组件模式
仅定义已批准页面需要的组件：应用外壳/导航、按钮、文本/邮箱/日期/时间输入、选择器/可见性控件、事件行/卡片和忙闲指示、成员/邀请项、对话框、校验/通知、加载/空/错误/无权限状态。适合时复用项目现有组件。

## 组件规格
每个组件记录用途、结构、变体、状态、Token 依赖、键盘行为、无障碍名称/描述、缩放行为、使用示例和反模式。

## 无障碍基线
支持键盘操作和合理焦点顺序；焦点可见；提供程序化标签并关联错误；对比度充分；不得只用颜色表达忙闲/可见性/权限；存在动效时尊重减少动态效果偏好。

## 验证
检查 Token 引用、缺失/未定义 Token、未记录原始值、组件复用、变体/状态覆盖和跨页面一致性。运行时截图对比必须等到另行授权应用实现后执行。
