# Visual References

- Status: DRAFT until the user approves a concrete Visual Direction.
- Selected reference family: Linear-inspired desktop productivity/tooling interfaces.
- This document records visual analysis, not product requirements or permission to copy third-party assets.

## Reference record template
For each reference, record:
1. Product/source name and exact source URL.
2. Capture date and relevant screen/context.
3. Observable characteristics (layout, hierarchy, density, typography, surfaces, color, iconography, motion).
4. Characteristics proposed to adopt and why they fit this app.
5. Characteristics to avoid and why.
6. Applicability to actual desktop constraints and approved PRD flows.
7. User decision: PROPOSED / ACCEPTED / REJECTED, with date/context.

## Initial direction hypothesis
Evaluate restrained neutral surfaces, precise alignment, compact but readable information density, clear type hierarchy, subtle separators, restrained accent use, consistent icons, and quiet interaction feedback. These are hypotheses only.

## Guardrails
- Do not copy Linear branding, logos, proprietary assets, or product-specific workflows.
- Do not infer dark mode, theme switching, keyboard-command palette, integrations, or features from reference products.
- Reference screenshots are inspiration and evidence only; editable specifications and approved tokens remain authoritative.
- Visual Direction Gate requires the user to explicitly accept one direction before final token values are proposed.
