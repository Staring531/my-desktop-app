# 线框设计

## 目的
在高保真视觉样式之前确定布局、层级和任务顺序。线框必须使用已批准的信息架构，并与已批准的设计系统契约兼容，不得提前锁定视觉样式。

## 进入条件
- 信息架构、流程和页面清单的结构基线已审阅并由用户接受。
- Visual Direction 和 Design Token/核心组件基线已获用户批准。
- 未解决的产品行为已明确记录；线框不得暗中替用户决定。

## 覆盖范围
覆盖所有获批页面或说明合理合并理由；支持的桌面窗口尺寸；主要/次要/破坏性/禁用操作；键盘焦点；校验和恢复；适用的空/加载/成功/无权限/错误状态。

## 单页面模板
1. 页面 ID/名称和角色/前置条件。
2. 主要任务和辅助信息。
3. 布局区域、层级和内容密度。
4. 已批准组件引用和语义 Token 角色（不得使用任意数值）。
5. 控件及操作语义。
6. 校验和反馈位置。
7. 状态变体。
8. 键盘/无障碍行为和焦点顺序。
9. 桌面窗口约束和缩放行为。
10. PRD AC、用户流程、组件和 Technical Design 引用。
11. 待确认问题、备选方案和有理由的偏差。

## 保真度顺序
文本草图 → 可编辑低保真线框 → 用户审阅信息架构/任务顺序 → 使用已批准 Token/组件制作高保真视觉规格。

不得把静态生成图片作为可编辑布局、组件语义或交互行为的唯一事实来源。源文件必须可审阅、可维护。
