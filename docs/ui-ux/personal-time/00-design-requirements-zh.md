## 1. 本阶段是什么

这是对仓库和已批准个人时间基线的检查。它记录候选界面和一份初始追溯。这些候选是提议，不是结构基线。

`docs/process/UI_UX_DESIGN.md` 第 2 节仍描述较早的桌面产品：一台电脑上的一份本地团队记录，并且没有网站、登录或邮箱验证。本阶段遵循较晚的个人时间批准。TD-PT-1 规定首期交付是现有 Next.js 网站只与现有 NestJS API 对话。注册、验证、找回密码和个人日历都在该已批准范围内。桌面 UI 包仍是另一份 PRD 的设计。

这里不选定视觉方向，不提出令牌取值，不修改应用文件，也不修改实施计划。

## 4. 后续设计必须保持的约束

- 首期是浏览器里一位已验证用户的日历。搜索、他人的日历、分享链接、团队和桌面客户端是后续交付。这个 UI 不给它们页面、链接或控件。
- API 决定是否有效。页面显示 `result` 和 API 返回的字段。它不第二次计算重叠、预览、时刻或证明结果。
- 共用失败保持共用。注册、验证、取消注册、登录和找回密码不得说明哪个字段被占用、账户是否存在或是否已验证。
- 失败正文不显示邮箱、密码、证明码、服务商文本或堆栈。
- 新事件默认私密，除非保存前选择公开。所有者在日历上能区分公开和私密。
- 重复类型在创建时选定。之后没有控件去改变已存储的类型。
- 没有仅日期的事件，没有提醒，没有全天事件，也没有“停止以后的重复并保留系列历史”的控件。
- 昵称裁剪和显示名遵循 PRD。页面不另定显示规则。
- 时区在注册时发送浏览器给出的 IANA 名称，之后发送用户选定的名称。页面不重新计算出现时刻。
- `choice_required` 的出现只提供 API 正文里的两个时刻。页面提交其中一个时刻和该公历日。它不发明第三个时刻。
- 跳过的日期不显示为已取消事件。缺席的出现不显示为已取消事件。
- 冲突条目只显示标题、开始和结束。系列保存还可以显示重复在窗口之后继续。那句话不是冲突。
- 用户取消，或操作没有完成时，账户删除、单次出现删除和系列删除都保持原状态。
- 页面不设计密码规则、证明有效期、会话时长、性能目标、邮件服务商或生产托管。
- DEC-079 没有无障碍标准。现有标记有语言和一个 `main`。这不是已批准的无障碍目标。

## 5. 候选界面

这些是给 Stage 1 的提议。它们对应 `05-application-design.md` 第 4 节的表单和第 1 节的路由。网址、页面合并和导航尚未决定。

| 候选 | 已批准的输入 | 页面可以显示的 API 结果 | 不在这个界面上 |
|---|---|---|---|
| C-01 注册 | 用户名、邮箱、密码、可选昵称、浏览器 IANA 时区 | `ok`、`registration_rejected`、`send_failed`、`operation_failed` | “用户名或邮箱已被占用”这类说明 |
| C-02 验证 | 用户提交的证明码 | `ok`、`verification_rejected` | 会话。路由表里验证本身不登录；登录是另一条路由 |
| C-03 取消注册 | 邮箱和密码，没有会话 | `ok`、`cancellation_rejected` | 删除已验证账户的控件 |
| C-04 登录 | 邮箱和密码 | `ok` 打开该用户的日历。`login_rejected` 和 `logged_out` 不显示日历和事件 | 对未知邮箱、未验证和错误密码使用不同文案 |
| C-05 开始找回 | 邮箱 | 邮件可发送时，可见结果与登录失败相同：`login_rejected`。邮件不能发送时为 `send_failed` | “证明已发送”这类说明 |
| C-06 完成找回 | 邮箱、新密码、证明 | `ok` 不打开日历。`recovery_rejected` | 新的会话 cookie |
| C-07 自己的日历 | 会话 cookie。`from` 和 `to` 是公历日 | 显示名、公开和私密、`scheduled`、`skipped`、`choice_required` 及其两个时刻 | 他人的日历、搜索、分享链接、团队 |
| C-08 保存事件 | 标题、开始、结束、可选地点和说明、可见性、创建时的重复类型 | `ok`，带 `conflicts`；系列还可带 `continuesAfterWindow`。`save_rejected`；月日期被拒绝时含 `monthTypes` 和 `missingDates` | 改变已存储事件的重复类型。仅日期的保存 |
| C-09 单次出现 | 分离时的原始开始时刻和提交内容。删除时的原始开始时刻 | 分离或删除单次出现后的 API 正文 | 已取消事件行 |
| C-10 账户 | 昵称、IANA 时区、删除账户、退出 | 昵称和时区结果。退出结束该会话。只有 API 表示删除已提交时，登录才消失 | 修改邮箱的字段。会话时长控件 |

C-02 记录的是路由事实，不是“验证和登录必须分成两个屏幕”的决定。只要已批准行为不变，Stage 1 可以把多个候选放在同一页。

## 9. 风险

| 风险 | 原因 | 本阶段的处理 |
|---|---|---|
| 一个 `docs/ui-ux` 树里有两套已批准的 UI | 修改桌面文件会改变已接受的设计。 | 个人时间文档放在 `docs/ui-ux/personal-time/`。 |
| 通用 UI 流程禁止网站和登录 | 照那句话做会漏掉已批准的个人时间 MVP。 | 本文件遵循个人时间 PRD 和 TD-PT-1，并写明这一点。 |
| 页面解释共用失败 | PRD 要求这些失败看起来相同。 | 第 4 节禁止这种解释。 |
| 页面计算时间或重叠 | 技术设计把该计算交给 API。 | 第 4 节禁止第二次计算。 |
| PT-023 和视觉系统分叉 | 计划写明呈现属于后续 UI/UX。 | 本阶段不改计划。差额等到设计被批准。 |
| 脚手架文案被当成产品 | 唯一页面仍写着 `My Desktop App`。 | 已记录。本阶段不改样式。 |
