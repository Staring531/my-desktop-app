## 1. 导航原则

- 首期交付是一个浏览器和现有 API。会话是 TD-PT-3 cookie。页面不另存一份日历再去隐藏字段。
- 未登录的人，包括退出后的所有者，可以打开无需会话的目的地。受保护的目的地显示 `logged_out`，并且没有日历、没有事件。
- 另一位已登录的人没有通往这个人的日历、事件或账户的目的地。
- 搜索、他人的公开日历、分享链接、团队和桌面客户端都没有目的地。
- 发出命令的页面显示该命令的 `result`。结果本身不是目的地。
- 页面发送用户输入的字段，并呈现 API 返回的正文。它不重新计算时刻、重叠、月预览或证明结果。
- 共用失败保持共用。没有目的地解释哪个值被占用，或账户是否存在、是否已验证。

## 2. 提议的结构

```text
浏览器
├── 无会话
│   ├── S-01 注册
│   ├── S-02 验证邮箱
│   ├── S-03 取消未验证的注册
│   ├── S-04 登录
│   ├── S-05 开始找回密码
│   └── S-06 完成找回密码
└── 当前会话
    ├── S-07 自己的日历
    │     └── 生成的双起点选择是 S-07 的一种状态
    ├── S-08 事件
    │     ├── 创建，或编辑系列或非重复事件
    │     └── 单次出现是 S-08 的一种状态，不是另一个目的地
    └── S-09 账户
          ├── 昵称
          ├── 时区
          ├── 退出
          └── 删除账户
```

与本结构一并提请接受的路径：

| 目的地 | 路径 |
|---|---|
| S-01 | `/register` |
| S-02 | `/verify` |
| S-03 | `/register/cancel` |
| S-04 | `/login` |
| S-05 | `/recovery` |
| S-06 | `/recovery/complete` |
| S-07 | `/calendar` |
| S-08 新建 | `/events/new` |
| S-08 已有 | `/events/:id` |
| S-09 | `/account` |

这些路径不在技术设计里。它们是导航提议。API 路由仍使用已批准的 `/api` 路径。

每个无需会话的目的地都可以从其他无需会话的目的地打开。登录成功后打开 S-07。验证和完成找回都不打开 S-07。它们回到 S-04，供之后登录。

已登录的目的地是 S-07、S-08 和 S-09。S-07 打开 S-08 和 S-09。S-08 和 S-09 回到 S-07。退出是 S-09 上的动作。成功之后，下一次受保护请求是 S-04 的未登录结果，这个会话的 cookie 不再打开 S-07。

## 3. 谁可以打开什么

| 行为人 | 目的地 | 不能打开 |
|---|---|---|
| 没有会话的人 | S-01 至 S-06 | S-07、S-08 和 S-09 的内容。直接请求显示 `logged_out`，没有日历和事件。 |
| 未验证的注册人 | S-02 和 S-03，仍然没有会话 | S-07。登录使用与未知邮箱或错误密码相同的 `login_rejected`。 |
| 已验证的所有者，当前会话 | S-07、该所有者事件的 S-08、S-09 | 他人的日历或事件。搜索、分享和团队。 |
| 其他已登录用户 | 该用户自己的 S-07 | 这位所有者的日历和事件。首期没有通往它们的路由。 |
| 退出后的所有者，或找回密码结束会话后的所有者 | S-04，以及其他无需会话的目的地 | 日历和事件，直到之后再次登录。 |

同一账户的第二个会话是另一个浏览器会话。退出第一个不会结束第二个。页面不提供会话列表。也不显示会话时长。

## 4. 每个已登录目的地包含什么

S-07 显示所有者在一个公历日期范围内的日历。页面发送 `from` 和 `to`，并显示返回正文中的出现：显示名、可见性、`scheduled`、`skipped` 和 `choice_required`。需要选择时，列出返回的两个时刻，并可以提交其中一个。跳过的日期和缺席的出现都不是已取消事件。所有者能区分公开和私密。初次打开的日期范围不在本文决定。

S-08 收集标题、开始、结束、地点、说明和可见性。新事件默认私密，除非保存前选择公开。重复类型只在创建时选择：不重复、每天、每周或每月。已有事件显示已存储的类型，并且不把另一种类型发出去。不存在的当地时间不会作为成功保存发送。当地时间出现两次时，只有保存里带了一个选定时刻才会存储。保存系列或非重复事件使用保存路由。修改单次出现，包括只改可见性，使用分离路由，并发送该次出现的原始开始时刻和提交内容。删除单次出现使用出现删除路由和该原始开始时刻。删除事件或系列使用事件删除路由。

S-09 修改昵称、修改 IANA 时区、退出当前会话和删除账户。注册不询问时区。它发送浏览器的 IANA 名称。之后的修改在这里进行。没有修改邮箱的字段。

删除账户、删除事件和删除单次出现都在同一目的地上有一个确认步骤。用户确认之前，页面不发送删除。取消则什么都不发送，屏幕上仍是已存储的账户或事件。该步骤的视觉形式属于后续交互工作，不是单独的目的地。

## 5. 提请接受的选择

| 选择 | 提议 |
|---|---|
| 登录后的落地页 | S-07。 |
| 验证或完成找回之后 | S-04。这两个命令都不打开日历。 |
| 事件工作 | 一个目的地 S-08。单次出现是该目的地的一种状态。 |
| 生成的双起点 | S-07 的一种状态。页面提交返回的那一对时刻中的一个。 |
| 无需会话的任务 | 六个目的地，避免把表单混在一起后解释共用失败。 |
| 破坏性确认 | S-08 或 S-09 上的一个步骤。不是新屏幕。 |
| 后续交付 | 没有目的地。 |
| 产品标题 | 未选定。Q-03 仍开放。脚手架标题不是本结构。 |
