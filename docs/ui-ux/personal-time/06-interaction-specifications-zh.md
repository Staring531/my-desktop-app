## 1. 共用命令行为

页面从一个区域发送一条命令，然后等待。命令在途时，发出命令的按钮保持标签，并忽略后续的点击、Enter 和 Space。PT-C09 以 `semantic.color.text-meta` 显示 `waiting`。这个词不是 API 结果。没有旋转指示。Cancel 和 Escape 只在命令发出之前可用。发出之后，页面等待结果。

拒绝不改变已存储的行，并保留已输入的值。共用失败不改变字段边框。留在原页时，`ok` 显示为字符串 `ok`，页面按返回正文重绘。不增加第二句成功说明。PT-C09 在显示 `result` 时是一条提示。`waiting` 不是那条提示。

Tab 按视觉顺序移动。页眉上的安静链接和任务标题在第一行，所以 Tab 先到达这些链接，再到达字段。聚焦的按钮由 Enter 和 Space 激活。聚焦的安静链接由 Enter 激活。在单行字段里按 Enter，激活该字段所属区域的主要按钮。在 Description 里按 Enter 插入换行，不激活 Save。这是对 Stage 4 “在任何字段里按 Enter 都激活区域主要按钮” 的唯一细化。否则多行说明无法包含换行。在 S-07 上，浅底和强调条出现在焦点所在控件的那次出现上。焦点离开该出现后，它们消失。浅底不选中时刻，也不改变 Save 或 Delete。冲突行不使用浅底。

只有当确认步骤没有命令在途时，Escape 才关闭已展示的 PT-C10 并且不发送。展示 PT-C10 时，焦点移到它的 Delete 按钮，然后 Tab 到达它的 Cancel 按钮。

Show range 和 Submit choice 在所需值出现之前使用安静外观并且不发送。所需值是两个公历日，或一个返回的时刻。控件保持可见。

## 2. 交互

### I-01 注册

- 意图：创建未验证的注册，或让服务器保持不变。
- 行动者：没有会话的人。流程 F-01。屏幕 S-01。
- 输入：用户名、邮箱、密码、可选昵称，以及浏览器的 IANA 名称。命令是 `POST /api/registrations`。
- 发送前：必填项为空时仍使用本页的主要按钮。服务器决定 `registration_rejected` 或 `save_rejected`。页面不发明字段级原因。
- 结果：`ok` 留在 S-01，显示字符串 `ok`，并且不打开 S-07。`registration_rejected`、`send_failed`、`operation_failed` 和 `save_rejected` 留在 S-01，并保留已输入的值。
- 取消：经安静链接离开页面时不发送。
- 不得发送：选定的时区、证明或会话。
- 追溯：AC-P01、AC-P02、AC-P17、AC-P33、AC-P39。

### I-02 验证

- 意图：验证账户，或让注册保持不变。
- 行动者：持有验证证明的人。流程 F-02。屏幕 S-02。
- 输入：证明码。命令是 `POST /api/registrations/verify`。
- 结果：`ok` 打开 S-04，并且不打开 S-07。`verification_rejected` 留在这里。
- 不得发送：邮箱、密码或会话。
- 追溯：AC-P01。

### I-03 取消注册

- 意图：移除未验证的注册，或让它留在原处。
- 行动者：没有会话的人。流程 F-03。屏幕 S-03。
- 输入：邮箱和密码。命令是 `POST /api/registrations/cancel`。
- 结果：`ok` 或 `cancellation_rejected` 留在 S-03。页面不说明三种拒绝情形中的哪一种。
- 不得发送：会话，或已验证账户的删除。
- 追溯：AC-P24。

### I-04 登录

- 意图：打开本会话的日历，或保持未登录。
- 行动者：没有可用会话的人。流程 F-04。屏幕 S-04。
- 输入：邮箱和密码。命令是 `POST /api/sessions`。
- 结果：`ok` 打开 S-07。`login_rejected` 留在 S-04，并使用与 S-05 相同的结果画法。
- 不得发送：证明。
- 追溯：AC-P01、AC-P25、AC-P34。

### I-05 开始找回

- 意图：请服务器开始找回，同时不得知邮件是否发出。
- 行动者：一个人。流程 F-05。屏幕 S-05。
- 输入：邮箱。命令是 `POST /api/recoveries`。
- 结果：`login_rejected`、`send_failed` 或 `operation_failed`。页面不增加“证明已发出”的句子。
- 不得发送：新密码或证明。
- 追溯：AC-P26、AC-P39。

### I-06 完成找回

- 意图：替换密码并结束已打开的会话，或什么都不改。
- 行动者：持有找回证明的人。流程 F-05。屏幕 S-06。
- 输入：邮箱、新密码和证明。命令是 `POST /api/recoveries/complete`。
- 结果：`ok` 打开 S-04，并且不打开 S-07。`recovery_rejected` 留在这里。
- 不得发送：会话 cookie。响应也不创建 cookie。
- 追溯：AC-P26。

### I-07 显示日历范围

- 意图：显示一段返回的范围，或显示没有可用的日历。
- 行动者：已验证的所有者，或没有可用会话的请求。流程 F-06 和 F-04。屏幕 S-07，已登出时是 S-04。
- 输入：键入的 `from` 和 `to`。命令是 `GET /api/calendar?from=&to=`。
- 发送前：任一日期为空时，Show range 不发送。Q-04 仍开放，因此页面不发明这一对日期。
- 结果：所有者正文画出返回的出现。空列表不画行。`logged_out`，或没有日历和事件的正文，画出 S-04 和 `logged_out`。
- 不得发送：计算出来的时刻、重叠、预览、搜索、分享、团队或其他日历。
- 追溯：AC-P03、AC-P07、AC-P18、AC-P34。

### I-08 提交生成的选择

- 意图：为一个生成的双起点存储一个返回的时刻。
- 行动者：`choice_required` 行上的所有者。流程 F-09。屏幕 S-07。
- 输入：该返回出现的公历日和其中一个时刻。命令是 `POST /api/events/:id/choices`。
- 发送前：两个时刻都未选，Submit choice 不发送。
- 结果：页面画出返回正文。不提供另一个时刻。
- 不得发送：第三个时刻，或从时区控件计算出来的时刻。
- 追溯：AC-P27、AC-P38。这里不能完成 AC-P14 和 AC-P36。S-07 打印返回的 `start` 和 `end`。单独的时钟标签需要 I-14 记录的技术设计变更。

### I-09 打开事件

- 意图：走到已接受的事件路径，并且不写入。
- 行动者：S-07 上的所有者。
- 输入：无。New event 打开 `/events/new`。Event 或 Series 打开 `/events/:id`。This occurrence 打开 `/events/:id` 的一次出现状态，并带上返回的开始时刻。
- 结果：没有命令，因此这个控件不产生 PT-C09。
- 不得发送：保存、分离或删除。
- 追溯：2026-11-25 接受的从 S-07 到 S-08 的路径。

### I-10 保存新的或已有的事件

- 意图：提交这个人提交的事件，或让已存储的事件保持不变。
- 行动者：所有者。流程 F-07。屏幕 S-08 的创建或系列编辑。
- 输入：标题、开始、结束、地点、说明和可见性。开始和结束是键入的公历日和时钟，按输入发送。创建还发送一种重复类型：`none`、`daily`、`weekly` 或 `monthly`。不重复选项发送 `none`。编辑不发送类型。创建时在选中一种类型之前，Save 不发送。
- 结果：`ok` 留在 S-08，显示字符串 `ok`，并画出 `conflicts`；为真时还画出 `continuesAfterWindow`。`save_rejected` 留在这里。月日期被拒绝时画出返回的 `monthTypes` 和 `missingDates`。键入的双起点只有在正文包含那些时刻时才画出选择。下一次保存可以带上其中一个时刻。
- 取消：Cancel 回到 S-07 并且不发送。
- 不得发送：重复类型的变更、第三个时刻或删除。
- 追溯：AC-P04、AC-P05、AC-P06、AC-P07、AC-P08、AC-P09、AC-P12、AC-P13、AC-P15、AC-P19、AC-P20、AC-P30、AC-P31、AC-P32、AC-P35、AC-P37、AC-P40。AC-P23 是 GAP-PT-01。只有返回正文已经包含两个时刻时，这个交互才画出选择。

### I-11 更改一次出现

- 意图：用提交的内容分离一次出现，或让系列保持不变。
- 行动者：一次出现状态中的所有者。流程 F-08。屏幕 S-08。
- 输入：返回的原始开始时刻和提交的内容。命令是 `POST /api/events/:id/detach`。
- 结果：页面画出返回正文。Series 切到同一路径的编辑状态并且不发送。
- 不得发送：重复类型。
- 追溯：AC-P10、AC-P11、AC-P21、AC-P22、AC-P28、AC-P29、AC-P31。

### I-12 确认删除

- 意图：只在确认步骤之后删除一次出现、一个事件或一个系列。
- 行动者：S-08 上的所有者。流程 F-08。
- 发送前：安静的删除控件展示 PT-C10 并且不发送。PT-C10 里的 Cancel 不发送，屏幕上仍是已存储的行。
- 输入：事件删除使用 `DELETE /api/events/:id`。出现删除使用 `DELETE /api/events/:id/occurrences` 和返回的原始开始时刻。
- 结果：已提交的删除在结果可见之后，经 Calendar 链接走向 S-07。没有提交的结果留在 S-08，屏幕上仍是原先的事件。跳过的行从不使用这个交互。
- 不得发送：PT-C10 之前的删除，或把缺席画成已取消事件的命令。
- 追溯：AC-P10、AC-P11、AC-P21、AC-P22、AC-P28、AC-P29。

### I-13 保存昵称

- 意图：存储、清除或保留昵称。
- 行动者：所有者。流程 F-10。屏幕 S-09。
- 输入：昵称字段。命令是 `PATCH /api/account`。
- 结果：返回的结果留在 S-09。S-07 显示下一次日历正文里的显示名。本页不计算该名称。
- 不得发送：邮箱变更。
- 追溯：AC-P33、AC-P39。

### I-14 保存时区

- 意图：存储一个新的 IANA 名称，或让当前名称留在原处。
- 行动者：所有者。流程 F-09。屏幕 S-09。
- 输入：键入的 IANA 名称。命令是 `PATCH /api/account/timezone`。
- 结果：`save_rejected` 留在 S-09 并且不写入。已提交的更改留在 S-09。S-07 在下一次日历正文里打印返回的 `start` 和 `end` 字符串。页面不从这些时刻另排一个时钟标签。与返回的 `start` 和 `end` 不同的时区时钟标签需要技术设计变更。本说明不做这个变更。
- 不得发送：会话时长。
- 追溯：打印返回的时刻不能完成 AC-P14 和 AC-P36。日历正文在 `scheduled` 时有绝对的 `start` 和 `end`，没有时钟标签字段。

### I-15 退出

- 意图：只结束本会话。
- 行动者：所有者。流程 F-04。屏幕 S-09。
- 输入：除当前会话外无其他输入。命令是 `DELETE /api/sessions/current`。
- 结果：已提交的退出画出 S-04，不保留日历或事件字段。同一账户的另一个会话不在这里处理。
- 不得发送：账户删除。
- 追溯：AC-P26、AC-P34。

### I-16 删除账户

- 意图：确认之后停用账户，或让它保持完整。
- 行动者：所有者。流程 F-11。屏幕 S-09。
- 发送前：安静控件展示 PT-C10 并且不发送。Cancel 不发送。
- 输入：只有 PT-C10 里的主要 Delete 按钮发送 `DELETE /api/account`。
- 结果：已提交的删除画出 S-04，并且不提供部分删除。没有提交的删除留在 S-09，账户字段仍在。
- 追溯：AC-P16。

### I-17 受保护的目的地

- 意图：显示已登录表面不可用。
- 行动者：没有可用会话、却打开 `/calendar`、`/events/new`、`/events/:id` 或 `/account` 的人。
- 输入：导航本身。这个交互不发送日历或事件命令。
- 结果：S-04 和 `logged_out`。不显示日历行，也不显示事件字段。
- 追溯：AC-P03、AC-P34。
