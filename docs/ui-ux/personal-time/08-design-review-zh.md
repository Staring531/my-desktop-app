## 发现

### UX-PT-REV-001

- 严重程度：major。需要产品决定：是。
- 影响：GAP-PT-01、S-08、I-10。
- 证据：手输的双起点是 `save_rejected`。已批准的错误正文不包含两个时刻。页面只在正文已经带有这些时刻时才画出选择。AC-P23 要求人选中一个时刻，包括 America/New_York 在 2026-11-01 的 01:30。
- 场景：用户键入一个发生两次的当地时间。
- 影响结果：可以显示 AC-P15。页面无法完成 AC-P23。
- 建议：保持缺口，直到技术设计返回这两个时刻，或者用户决定页面只显示 `save_rejected`。

### UX-PT-REV-002

- 严重程度：major。需要产品决定：否。
- 影响：F-07、S-08 清单、已接受的页面说明、I-10。
- 证据：流程和清单把成功的保存送到 S-07。已接受的页面说明把 `ok`、冲突和继续句留在 S-08。S-07 没有冲突行。
- 场景：保存成功，并且有重叠或 `continuesAfterWindow`。
- 影响结果：警告会离开唯一画出它的表面。
- 建议：让流程和清单符合已接受的页面规则。已于 2026-11-25 写入。

### UX-PT-REV-003

- 严重程度：major。需要产品决定：是。
- 影响：已接受的信息架构、F-02、S-02、S-06、I-02、I-06。
- 证据：信息架构写明验证和完成找回回到 S-04，并且不打开日历。I-02 和 I-06 在 `ok` 之后留在 S-02 或 S-06。
- 场景：验证或完成找回返回 `ok`。
- 影响结果：下一页要么是登录，要么仍是证明页。
- 建议：让 Stage 5 符合已接受的信息架构，或请用户保留留在原页的行为。

### UX-PT-REV-004

- 严重程度：major。需要产品决定：是。
- 影响：PT-C02、PT-C09、S-01、S-02、S-03、S-06、S-09。
- 证据：在途时标签不变，也没有旋转指示。`ok` 不增加句子。这些屏幕上的字段不改变。
- 场景：留在原页的命令正在途中，或返回 `ok`。
- 影响结果：就绪、等待和成功看起来相同。第二次提交可以把已完成的验证或取消变成拒绝。
- 建议：规定看得见的在途状态和看得见的 `ok`。它不解释哪个字段失败，也不说证明已发出。

### UX-PT-REV-005

- 严重程度：major。需要产品决定：是。
- 影响：PT-C01、S-04、I-17、S-07 线框。
- 证据：PT-C01 写明带 `logged_out` 的受保护表面保留该页，并且只显示 PT-C09。已接受的 S-04 说明在受保护路径上画出登录表单。
- 场景：没有会话的人打开 `/calendar`、`/events/new`、`/events/:id` 或 `/account`。
- 影响结果：页面要么只有结果，要么是登录表单加上 `logged_out`。
- 建议：选定一种行为，并让组件、页面、交互和线框一致。

### UX-PT-REV-006

- 严重程度：major。需要产品决定：否。
- 影响：PT-C04、S-07、I-08。
- 证据：PT-C04 曾写明用户键入与生成选择一起提交的公历日。已接受的页面把该日期显示为返回文字，并且不可编辑。
- 场景：提交一个 `choice_required` 行。
- 影响结果：键入的日期可能不同于 API 和 PT-023 要求的日期。
- 建议：From 和 To 保持键入，选择日期显示返回值。已于 2026-11-25 写入。

### UX-PT-REV-007

- 严重程度：major。需要产品决定：否。
- 影响：PT-C06、S-08 创建、I-10。
- 证据：四种重复都未选时，Save 已经是主要按钮。已存储的类型是 `none`，不是 `non-repeating`。
- 场景：用户保存新事件时没有选择类型，或页面发送看得见的词 `non-repeating`。
- 影响结果：请求可能漏掉类型，或发送存储不使用的值。
- 建议：在选中一种之前让 Save 保持安静，不重复选项发送 `none`。已于 2026-11-25 写入。

### UX-PT-REV-008

- 严重程度：major。需要产品决定：否。
- 影响：PT-C05、S-08。
- 证据：开始和结束曾被写成只有当地时间。AC-P06、AC-P09、AC-P15 和 AC-P23 同时需要公历日和时钟。系列存储锚点日期以及当地开始和结束。
- 场景：用户创建月系列、在某个日期输入缺失的当地时间，或输入没有时钟的日期。
- 影响结果：只有时钟的字段无法表达这些输入。
- 建议：写明开始和结束是键入的公历日和时钟，按输入发送。已于 2026-11-25 写入。

### UX-PT-REV-009

- 严重程度：minor。需要产品决定：否。
- 影响：共用焦点规则、冲突行。
- 证据：任何含有焦点的行都会得到强调色浅底和前导条。冲突行规定没有强调色。
- 场景：焦点落在冲突行内。
- 影响结果：冲突行得到原本留给选中出现的强调色。
- 建议：焦点环留在控件上，浅底和前导条只用于选中的出现。已于 2026-11-25 写入。

### UX-PT-REV-010

- 严重程度：minor。需要产品决定：否。
- 影响：`tokens/design-tokens.json`。
- 证据：`neutral-700` 曾比 `neutral-800` 更深。
- 场景：实现者按编号选择原始色。
- 影响结果：次要文字和辅助文字可能被对调。
- 建议：编号越大颜色越深，并保持语义颜色的十六进制值。已于 2026-11-25 写入。
