# Page Specifications

## Purpose
Describe how approved components and tokens compose each approved screen. This document does not create new screens or product behavior.

## Per-page contract
- Screen ID, name, status, actor, permissions, and preconditions.
- Primary user goal and relevant user-flow IDs.
- Layout regions, hierarchy, density, content, and desktop window constraints.
- Component inventory with component-spec references.
- Semantic/component token references; no arbitrary visual values.
- Initial/loading/populated/empty/error/denied/disabled/success states as applicable.
- Interaction entry/exit, validation, cancellation, command result, and feedback.
- Keyboard/focus/accessibility behavior.
- PRD requirement/AC and Technical Design traceability.
- Open questions, assumptions, deviations, and user decisions.

## Page consistency
Shared navigation, spacing, typography, surface, and feedback patterns must remain consistent. Page-specific deviations require rationale and review. Do not create profile/settings/notification or other surfaces without approved requirements.
