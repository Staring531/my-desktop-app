# 信息架构

- 状态：候选提案，需用户审阅。
- 范围：仅 Version 1 桌面应用。

## 导航原则
导航层级浅、以任务为中心；清楚显示唯一团队上下文；按已批准角色权限展示操作。不增加 Website、Admin、API、登录或同步入口。

## 候选结构
以下为提案，不是最终页面决策。

~~~text
桌面应用
├── 会话 / 团队入口
│   ├── 绑定允许的邮箱上下文
│   ├── 创建团队（记录不存在或已解散）
│   └── 待处理邀请（被邀请人）
└── 活动团队
    ├── 忙闲总览
    ├── 成员
    │   ├── 成员详情 / 可见事件
    │   └── 邀请管理（维护者）
    └── 我的日程
        ├── 事件列表 / 日历式视图
        └── 创建 / 编辑事件
~~~

## 按角色展示
- 当前成员：忙闲总览、个人日程、团队可见事件和本人事件操作。
- 维护者：成员/邀请管理、角色交接、移除成员，以及 PRD 允许的保留事件管理。
- 被邀请人：仅能看到待处理邀请及接受/拒绝操作。
- 已移除成员：无法访问活动团队；只能通过后续邀请重新加入。

## 待确认的设计选择
忙闲看板是否为首页、成员事件如何呈现、事件编辑使用模态框/侧边面板/独立页面。对可用性有实质影响的选择应向用户提供备选方案。
