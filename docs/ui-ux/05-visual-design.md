# Visual Design

## Direction
The selected direction is **System-First, Linear-inspired**. Linear is a reference for restrained, precise, information-dense desktop tooling—not a target to clone. The exact visual direction must be proposed from repository evidence and explicitly approved by the user before final token values are established.

## Visual characteristics to evaluate
- Neutral, low-noise surfaces with a restrained accent strategy.
- Clear typographic hierarchy and deliberate information density.
- Precise alignment, consistent spacing, subtle separators, and restrained elevation.
- Stable desktop navigation/content structure appropriate to the actual application.
- Consistent icon family, stroke/size, focus treatment, and interaction feedback.
- Readable busy/free and visibility distinctions that never depend on color alone.

These are design hypotheses, not approved colors, fonts, dimensions, or layout decisions.

## Required specification
Record approved direction, reference characteristics and attribution, what to adopt/avoid, hierarchy, semantic color roles and contrast, typography and truncation, spacing/density, surfaces/borders/focus, icon semantics and text alternatives, state styling, and desktop-window behavior. Link each visual decision to approved tokens and components.

## Constraints
Do not copy Linear branding, logos, product-specific screen patterns, or proprietary assets. Do not imply business states absent from the PRD. Define light/dark theme behavior only if supported by existing product direction and approved by the user; do not invent a theme-preference feature. Full branding/marketing identity is out of scope. Page-level deviations from the design system must be documented and justified.
