description: Reusable System-First UI/UX workflow from repository readiness through approved design-system handoff.
---

Read `docs/process/DEVELOPMENT_WORKFLOW.md`, `AGENTS.md`, and follow `docs/process/UI_UX_DESIGN.md`. Read approved PRD, Technical Design, Implementation Plan, decision records, and repository evidence.

Follow the ordered stages and user gates. Establish structural requirements. Write and confirm a visual brief (audience, personality adjectives, anti-goals, Taste constraints) before proposing directions. Propose directions that differ in posture, with at least one contemporary and expressive, and no default reference family. Obtain approval for an openable page set (primary screen, entry or form screen, state-heavy screen, navigation shell). Then extract tokens, propose explicit extensions for every required state the page set does not show (state matrix), and obtain approval for tokens and core component contracts before high-fidelity design at scale. Classify each constraint as Scope or Taste and list them separately. Use the machine-readable token baseline and matching documentation. Maintain requirement traceability and preserve scope.

Judge visual quality on rendered output: screenshots at a narrow and a wide viewport, measured contrast ratios, and a brief-fit check. Missing evidence is NOT RUN, never PASS.

A skill is a reusable procedure, not an isolated subagent. Use independent review only with native delegation and disclose fallback limitations. Do not write application code, install dependencies, or modify the plan without approval. UI/UX approval is not coding authorization.
